# Security and responsible disclosure

BoreWatch is an educational prototype and is not intended for operational records or sensitive data.

Do not submit credentials, personal information, precise private borehole locations, water-quality records, inspection photographs or other restricted data in public issues, pull requests or repository files. Use synthetic fixtures only.

If you discover a security concern, do not create a public issue with exploit details or sensitive evidence. Contact the repository owner privately through GitHub’s private vulnerability reporting feature if it is enabled, or use a private communication channel already provided by the repository owner. Do not assume that a report has been received until acknowledged.

Before any operational deployment, the responsible organization must define a security contact, incident-response process, access controls, data-retention rules, backup/restore procedures and applicable privacy obligations.
